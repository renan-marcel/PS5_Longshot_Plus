# Virtual amiibo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** OoT on the PS5 reads a virtual amiibo chosen in a new Amiibo tab, from an AmiiboAPI catalogue (with pictures) the builder downloads when "Download amiibo" is ticked.

**Architecture:** A game-free C core (`host/amiibo_core.c`) holds the nfp state machine, the info structs and the application areas; `host/nn_nfp.c` binds the game's `nn::nfp` imports to it with `HLE(...)`. The renderer's menu reads the builder-made catalogue (`amiibo/amiibo.idx` + `figures.pak`) and drives the core through four new `MkwVkHost` calls. The builder's eighth step (`ps5/builder/amiibo.py`) downloads AmiiboAPI at a pinned commit and writes the catalogue.

**Tech Stack:** C11 (host), C++20 + Dear ImGui (gpu/vk), Python 3.12 + Pillow + zstandard (builder), zstd (runtime, `third_party/zstd`).

**Spec:** `docs/superpowers/specs/2026-11-26-amiibo-design.md`

## Global Constraints

- Branch `feature/amiibo` (from `fork/develop`); PR into `develop` of `renan-marcel/PS5_Longshot_Plus`.
- No Nintendo picture, key, dump or game-derived file in the repository, a release or a kit. Test fixtures are made-up bytes and pictures drawn by the test.
- No emuiibo code (GPLv2-only). Fritchii/Lichii (GPLv3) may be adapted with a credit line in the file header: `Adapted from Fritchii (Frizti/Fritchii, src/core/hle/service/nfc, GPLv3)`.
- nfp result codes: `module 115 | description << 9`: DeviceNotFound `0x8073`, InvalidArgument `0x8273`, WrongApplicationAreaSize `0x8873`, WrongDeviceState `0x9273`, TagRemoved `0xC273`, ApplicationAreaIsNotInitialized `0x10073`, WrongApplicationAreaId `0x13073`, ApplicationAreaExist `0x15073`.
- Struct sizes: TagInfo `0x58`, ModelInfo `0x40`, CommonInfo `0x40`, RegisterInfo `0x100`, ApplicationArea `0xD8`.
- Device states (u32): Initialized 0, SearchingForTag 1, TagFound 2, TagRemoved 3, TagMounted 4, Unavailable 5, Finalized 6.
- AmiiboAPI pinned commit: `6115745` (N3evin/AmiiboAPI master at planning time; the full hash and the archive's SHA-256 are taken in Task 5 and written into `amiibo.py`).
- Pillow pin `pillow==13.0.0` (as `nx2/prompt_requirements.txt`).
- Menu text in English. Tab order: Graphics, Audio, Gameplay, Controls, **Amiibo**, Debug.
- A change to `MkwVkHost` bumps `MKWVK_API_VERSION` (24 → 25).
- Every C/C++ test is a `tests/test_*.py` that compiles with `RUN_ALL_ARGS` placeholders (`{cc}`, `{cxx}`) and runs under `python -I -B tests/run_all.py`; a Python dependency is declared in `RUN_ALL_MODULES`.
- `python -I -B tests/run_all.py` before the PR: develop's baseline is 73 failing checks (none may be added).

## Review Focus

1. **The game calls nfp in a state the core does not expect** (e.g. `GetTagInfo` before `StartDetection`, `Mount` twice): it must get Fritchii's result code, never a crash or an out-of-range write. Task 2's test drives every call from every state.
2. **The player touches, removes and touches again while the game is mounted**: removal unmounts, signals deactivate, and the next touch only finds while searching. Task 2.
3. **A catalogue missing or half-written** (`amiibo.idx` without `figures.pak`, a truncated pack, a record whose picture runs past the end): the tab still lists names, the card shows the silhouette. Task 6.
4. **A figure name with non-ASCII characters** ("Pokémon", "Ōkami") or longer than the record: the builder writes printable ASCII cut to fit, the register info gets ≤ 10 characters. Tasks 5 and 2.
5. **The guest passes a buffer smaller than the area** (`GetApplicationArea` with size < area) or larger than `0xD8` to `Set/Create`: copy at most the smaller, `WrongApplicationAreaSize` over `0xD8`. Task 2.
